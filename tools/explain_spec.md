# Разборы вопросов ITPEC FE — спецификация

Студент (русскоязычный) готовится к экзамену **ITPEC Fundamental IT Engineer (FE)**.
Вопросы на экзамене — на английском, 4 варианта (a–d), один верный.
Вопросы ITPEC повторяются между годами, поэтому каждый разбор должен помогать
**понять и запомнить**, а не только назвать букву.

Для каждого вопроса нужен JSON-файл с:
1. **точным переводом** вопроса и всех вариантов на русский;
2. **глоссарием** ключевых английских терминов и аббревиатур;
3. **решением** — как прийти к ответу (рассуждение или расчёт по шагам);
4. **разбором каждого варианта** — что он на самом деле описывает и почему он
   верен/неверен;
5. **приёмом запоминания** — только если есть настоящий, работающий.

## Входные данные и выход

Для каждого вопроса нужны: картинка (`web/data/img/<экзамен>/qNN.webp`), ключ
(`answer` в `web/data/<экзамен>.json`) и список его повторов (поле `cluster`:
все вопросы с тем же `cluster` — версии одного вопроса).

- `answer` — **официальный ключ ITPEC**. Разбор обязан объяснять именно его.
- **Всегда открывай картинку**: поле `text` извлечено автоматически и бывает
  искажено — пропадают таблицы, рисунки, индексы, скобки у вариантов, формулы.
  Картинка — источник истины.
- Версии одного вопроса разбирай вместе, но каждую — по её собственной
  картинке: **порядок вариантов и буква ответа между версиями могут отличаться**.

Результат — по файлу `<ID вопроса>.json` в любой папке, затем
`python3 tools/build_explain.py <папка>` сверяет их с банком и добавляет в
`web/data/explain/`.

```json
{
  "answer": "d",
  "question": "…",
  "options": { "a": "…", "b": "…", "c": "…", "d": "…" },
  "terms": [ { "term": "CPI", "full": "Cost Performance Index", "ru": "индекс выполнения стоимости" },
             { "term": "relationship marketing", "ru": "маркетинг взаимоотношений" } ],
  "solution": "…",
  "why": { "a": "…", "b": "…", "c": "…", "d": "…" },
  "memo": "…",
  "note": "…"
}
```

`note` — необязательное поле, только по правилу «Если ключ кажется неверным» ниже.

### Разметка текста

Обычный текст. Перенос строки — `\n`. Жирный — `**…**` (парные звёздочки).
Строку можно начать с `• ` для перечня. **Никакого HTML, заголовков `#`,
блоков кода, таблиц markdown.** Формулы — обычным текстом с Unicode: × ÷ − ≤ ≥ ≈ → √ ².

## Правила по полям

### `question` — перевод формулировки (без вариантов)

- Полный и точный перевод, естественный русский язык. Ничего не опускать —
  все условия, оговорки («Here, …» → «Здесь …», «Other overheads can be ignored»),
  числа, единицы.
- **Числа — ровно как в оригинале** (те же разделители: `100,000`, `0.25`), чтобы
  сверялись с картинкой и вариантами. Имена/обозначения (Company A, product X,
  activity D) не переводить.
- **Аббревиатуры:** при первом появлении оставить аббревиатуру и дать в скобках
  английскую расшифровку и русский перевод: `CRM (Customer Relationship
  Management — управление взаимоотношениями с клиентами)`. Если в оригинале
  расшифровка уже есть — всё равно должны присутствовать все три части.
  Это относится и к аббревиатурам в вариантах (в `options`).
  **Исключение:** если расшифровка аббревиатуры сама является ответом на вопрос
  (например, «что означает P в PEST?»), в `question` и `options` её не раскрывай,
  чтобы перевод не выдавал ответ, — дай расшифровку в `terms` и `solution`.
- **Ключевые английские термины,** на которых держится вопрос, после русского
  перевода оставлять в скобках по-английски: `маркетинг взаимоотношений
  (relationship marketing)` — на экзамене студент увидит именно английский термин.
- Таблицы из вопроса — строками `Название: значение` или `A | B | C` через `\n`.
- Рисунки (стрелочные диаграммы, графики, схемы): кратко опиши в квадратных
  скобках то, что нужно для решения: `[На рисунке — стрелочная диаграмма:
  A (3 дня) → C (5 дней) …]`.
- Вопрос в старом формате бывает с формулировкой «Which of the following…» —
  переводи «Что из перечисленного…» / «Какое из следующих…».

### `options` — перевод каждого варианта

- Полный перевод каждого варианта, те же правила про аббревиатуры и термины.
- Числовые / формульные варианты — как есть (`"1.25"`, `"EV / AC"`).
- Если варианты — картинки или пары/наборы из рисунка, опиши каждый кратко
  и однозначно.

### `terms` — глоссарий

0–6 элементов: аббревиатуры и английские термины из вопроса и вариантов,
которые **стоит знать на экзамене**. `term` — как в оригинале, `full` — английская
расшифровка (только для аббревиатур), `ru` — русский перевод/суть в 2–10 слов.
Не включай очевидную лексику (company, product, system).

### `solution` — как решать

- Начни с того, **на что смотреть / какой это тип задачи** (например,
  «Задача на точку безубыточности», «Ключ — слово *relationship*»).
- Для расчётов — шаги `**Шаг 1.** …` с формулами и промежуточными числами;
  обязательно сверь итог с вариантами.
- Для определений — суть понятия своими словами + по какому признаку в
  варианте его узнать.
- Закончи явным указанием верного варианта: `→ d)`.
- Объём — сколько нужно для понимания: обычно 2–8 строк. Без воды.

### `why` — разбор всех вариантов

Для **каждого** варианта:
- неверный: **что он на самом деле описывает** — назови понятие по-русски и
  по-английски (отвлекающие варианты в ITPEC обычно являются определениями
  других экзаменационных терминов — это бесплатное повторение), и почему не
  подходит под вопрос; для расчётов — какая ошибка даёт это число;
- верный: начни с `**Верно.**` и коротко подтверди.
1–3 предложения на вариант.

### `memo` — как запомнить

Только **настоящий** приём: этимология английского слова, мнемоника,
противопоставление пары понятий, шаблон формулы, «если видишь X в варианте —
это Y». Если ничего толкового нет — `null`. Не выдумывай натянутых мнемоник.

### Если ключ кажется неверным

Официальный ключ почти всегда верен — перепроверь условие по картинке
(перевод вопроса мог исказиться). Если после тщательной проверки ты всё равно
уверен, что ключ ошибочен: всё равно поставь `answer` = ключ, объясни логику,
ведущую к ключу (если она есть), и добавь поле `note` с кратким описанием
сомнения. Никогда не меняй `answer`.

## Качество

- Всё на русском с правильной орфографией и типографикой («ёлочки», тире —).
- Терминология — как принято в русскоязычной литературе по ИТ/менеджменту
  (PMBOK, ITIL, бухучёт). Если устоявшегося перевода нет — описательный перевод
  + английский термин в скобках.
- Факты должны быть верны. Не уверен в определении — опирайся на стандартные
  источники (PMBOK, ITIL 4, ISO/IEC 12207, IPA/ITPEC syllabus), не фантазируй.

## Эталоны

Разборы `2025A-A-50` (определение) и `2024S-A-42` (расчёт) в
`web/data/explain/2025A-A.json` и `2024S-A.json` — эталон стиля, глубины и
формата. Прочитай их перед началом.

Чтобы буквы не перепутались, после генерации проверь: `**Верно.**` должно
начинать ровно один `why` — у варианта, совпадающего с ключом.
